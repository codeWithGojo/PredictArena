# Phase 1 security decisions

- **State contains the Google secret.** Terraform `sensitive` redacts normal CLI output, not state or plan files. S3 is private, versioned, encrypted and TLS-only. Restrict state readers, protect recovery copies and do not upload plan artifacts. Secret rotation leaves historical state versions containing prior values. No provider/payment secret is created. [Terraform sensitive data](https://developer.hashicorp.com/terraform/language/manage-sensitive-data).
- **Cognito/PKCE.** The browser client has no secret and allows only authorization code, not implicit flow. Callback/logout/origin URLs are exact HTTPS allowlists. PKCE S256, state and nonce must be implemented by the frontend; there is no Terraform switch guaranteeing every client uses PKCE. Email/password and Google both use managed login. Google attribute mapping and email delivery require real sign-in verification. No automatic linking of Google and password identities is implemented.
- **JWT and entitlement.** Gateway validates issuer/audience/scope; Lambda also rejects non-access tokens, the wrong client, missing scope and invalid sub. Owners come only from Gateway claims. Every premium request performs a fresh strongly consistent users-table GetItem and requires `plan=premium`, a future `premiumUntil` and `entitlementRevoked=false`. Storage errors fail closed with 503; missing profiles return 409; inactive entitlements return 403. `/me` derives effective plan at read time. JWT plan claims and TTL are never authorization sources. [AWS JWT authorizers](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-jwt-authorizer.html).
- **Runtime IAM.** Each route has its own role, exact log-group permissions and route-scoped invocation permission. Public stub roles can only log. Private roles additionally GetItem from the users table. Only GET /me can read the exact Cognito pool and conditionally create a profile. The separate pool-scoped post-confirmation initializer can only PutItem users and log. There is no Scan, UpdateItem, DeleteItem, sports-table access, provider/payment secret access or arbitrary Lambda invocation. Runtime permissions boundaries are controlled by bootstrap, not CI.
- **Initialization privilege.** PutItem can replace records at the IAM layer, so safety also depends on the trusted helper's `attribute_not_exists(pk) AND attribute_not_exists(sk)` condition. Both initialization paths create only free, verified users and cannot overwrite existing rows. No request body supplies identity or entitlement fields. No profile-update success is acknowledged in Phase 1. The users schema's inert payment metadata fields do not implement any payment behavior.
- **Stub isolation.** Sports success specimens require both `stage=dev` and `stub_responses=true`; Terraform rejects production enablement and runtime independently blocks it. All responses are private/no-store; samples are marked by a header, source or modelVersion and stale status. The default deployment returns DATA_UNAVAILABLE until the sports track is connected. No fabricated live snapshots or accuracy claims are published.
- **GitHub trust.** Trust is restricted to `aud=sts.amazonaws.com` and `repo:codeWithGojo/PredictArena:environment:dev|prod`. Environment reviewers must verify internal PR code before any cloud credentials or state secrets are available. Fork PRs never get credentials. Trusting an environment does not itself constrain which branch can use it: GitHub deployment branch rules and reviewer protection are mandatory. Plan roles cannot modify application resources; apply roles cannot modify bootstrap roles or runtime boundaries. No long-lived AWS keys are used. [GitHub AWS OIDC](https://docs.github.com/en/actions/how-tos/secure-your-work/security-harden-deployments/oidc-in-aws).
- **Deployment privilege requiring account review.** API Gateway IDs are allocated on creation, so bootstrap's deploy policy initially permits API control-plane writes under regional `/apis/*` and `/tags/*`. Cognito metadata reads use regional pool ARNs; writes use stage/project tags. HTTP API log-delivery/resource-policy actions require Resource `*`, constrained by requested region. These broader control-plane permissions are not granted to runtime roles. Prefer separate AWS accounts for stronger production isolation and narrow the API management ARN set after the first deployment. Real account validation is required for tag-condition behavior, SCPs and quotas. IAM was not broadened to bypass Terraform validation. [HTTP API logging permissions](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-logging.html).
- **Logs and errors.** API access logs contain only request ID, route key, status and response length. Handlers never log tokens, email, request bodies or secrets. All app errors have the contract envelope; 503 has Retry-After. Gateway's pre-Lambda rejection errors may retain AWS's native shape, as the contract permits.
- **State isolation and deletion.** CI can access only its stage state and lock object, not bootstrap state. Reserved `env:/` bucket listing supports Terraform workspace discovery but no CI role may read/write state there. Use default workspace only. Production pool/tables have deletion protection, and the bootstrap bucket has prevent_destroy. These controls do not replace plan review. [S3 native state locking](https://developer.hashicorp.com/terraform/language/backend/s3).
- **Launch gates.** An AWS-backed plan/apply, live OAuth tests, API authorization checks and data-track integration remain required. Legacy public Vercel model routes must be removed by their owner before any paid launch. Phase 2 is excluded: no slips/bets/billing/webhook routes, related tables, streams or scheduled workers.
